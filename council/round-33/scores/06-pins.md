## What is right

Build pin 0: ink bbox x 24..30 (centre 27.0) in a tile 10..44 (centre 27.0), ink y 78..86 (centre 82.0) in a tile 65..99 (centre 82.0). Same for pins 1..3 (glyph cx 64.5/102.5/141.0 against tile centres 65.0/103.0/141.0). Row tile letter: bbox 24..30 × 115..122 inside the 19..34 × 111..126 tile. That is `ui.rs:520-524` plus `holder.set_homogeneous(true)` at `ui.rs:400`.
- Geometry tracks the reference: 35px tiles, 3px gaps, left edges 10/48/86/124 against the reference's 8/47/85/124; corner inset measured row by row (17,15,13,12,12,11,11,10 from y=65 to y=72) gives a radius of about 9px, the reference is 15,13,12,11,10,10,9 over the same span. `css.rs:142` `.pin { border-radius: 9px }`.
- Only one mark is ever drawn. `mark()` hides the overlay's letter when a surface arrives (`ui.rs:415-418`) and restores it when the icon disappears (`ui.rs:424-427`); both the letter and the icon box opt out of `show_all` (`ui.rs:529-531`, `ui.rs:545-546`), so `render_pins`' own `show_all` (`app.rs:916`) cannot resurrect the letter over a favicon.
- Letter contrast is measured, not guessed: `PIN_FG` #6A6A68 on #F6F6F6 = 5.02:1 (`css.rs:27`), live letter #545452 on #DBDBD9 = 5.47:1 (`css.rs:29`). An empty title or URL falls back through host to 'N' (`app.rs:51-58`), so a tile is never blank.

## What costs points
- **A pinned tab can never be unpinned.** The pin's press arm handles only buttons 1 and 2 (`app.rs:900-906`); the menu that offers "Unpin Tab" (`app.rs:1705-1712`) is reached only from a row's button 3 (`app.rs:819`), and pinned tabs are filtered out of the rows (`app.rs:776`). `keys::SHEET` (`keys.rs:157-206`) has no pin verb and `main_menu` (`app.rs:1735-1752`) has no Pin item. Smallest fix: add `3 => app.tab_menu(id, event)` to the pin arm at `app.rs:903`. Cost: 1.5.
- **The letter tile vanishes on the row you are on.** `.tile` is #F1F1F1 (`css.rs:272`) and `.row.live` is `wash` #EFEFEF (`css.rs:151`, `palette.rs:106`): 1.018:1. Measured in `03-tabs.png`: tile fill at (20,200) = srgb(239,239,239), row background at (150,200) = srgb(239,239,239) identical; in `round-33-dark/03-tabs.png` both are srgb(58,58,58). The Are.na row therefore shows a bare "A" floating while every other row shows a chip. Smallest fix: add `.row.live .tile { background-color: {card}; }`. Cost: 0.8.
- **The wrap count is derived from a stored preference, never from the sidebar.** `app.rs:882` reads `self.prefs.borrow().side_width`; that field is only ever read after launch (grep `side_width` → `app.rs:267,300,882`, `ui.rs:78`, `store.rs:35,95,124`), and the Paned that owns the real width has no `notify::position` handler (`ui.rs:73-77`). Drag the handle and the column count is stale until relaunch, and the width is never saved. `pins_holder` also has no scroller and sits above the only scrolled child (`ui.rs:120-130` vs `ui.rs:137`), so a dozen pins push the tab rows down with no way back. No evidence covers this: every shot has four pins, and `stress.py` has no pin-wrap check. Smallest fix: `let usable = self.ui.pins.allocated_width();` and store the Paned position on release. Cost: 0.7.
- **The favicon path has never been rendered, and it is knowingly soft.** `grep -c 'rel="icon"' tools/fixtures.py tools/demo/*.html` = 0, so all 15 states are letters: `02-pins.png` and `03-tabs.png` both show the "Office Commun" row as a grey "O" tile (`/tmp/rowmark.png`) where the reference shows the real double-circle mark (`/tmp/ref_rowmark.png`). The scale is `gtk::Image::from_surface` + `set_pixel_size(22)` for a 16px favicon (`ui.rs:348-355`, comment: "GTK scales the surface"), i.e. an interpolated upscale with no crisper path. The live pin is likewise unphotographed: sampling the four pin fills in all 15 light shots gives 0.956/0.953/0.958/0.956 mean, i.e. never #DBDBD9. Smallest fix: add one fixture route serving a `<link rel="icon">` PNG and one shot with a pinned, active tab. Cost: 0.5.
- **The plus row's title sits 2px left of every tab title.** `app.rs:833-836` packs `icons::area(Icon::Plus, 16, …)` straight into the hbox, while rows put their mark in an 18x18 box (`ui.rs:465-466`). Measured in `03-tabs.png`: "New tab" on the plus row bbox x 41..89 (y 234..242) against x 43..91 for the rows above it. Smallest fix: put the plus in a box with `set_size_request(18, 18)`. Cost: 0.3.
- Minor: `.pin:hover` #EFEFEF on #F6F6F6 is 1.05:1 (`palette.rs:108-109`), so a pin has almost no hover state; and a pinned blank tab's tooltip is `title` = the raw URL (`app.rs:866`), which is `""` for a new pinned tab, so it shows nothing at all.

## The three changes that would raise this score most
1. Give the pin a right-click: `3 => app.tab_menu(id, event)` in the press arm at `app.rs:903`, so "Unpin Tab" is reachable (pinning is currently one-way, and no key or menu item does it).
2. Give `.row.live .tile` its own fill so the active row's letter chip stops disappearing at 1.018:1 (`css.rs:272` against `css.rs:151`).
3. Compute `across` from `self.ui.pins.allocated_width()` and persist the dragged sidebar width, plus scroll `pins_holder` so more than ten pins cannot push the tab list off the column.
