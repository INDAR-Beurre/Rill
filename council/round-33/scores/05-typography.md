## What is right

- Monospace is used only where it belongs, and never by accident. `{mono}` appears in exactly four rules: `.erraddress` (`src/css.rs:194`), `.keycap` (`:245`), `.keyhint` (`:261`), plus code inside the reader sheet (`assets/reader.js:75`). Every other rule says `{font}`. In `09-missing.png` the URL `http://127.0.0.1:8099/missing` is visibly mono (measured 201x8, fixed-pitch runs) while the sentence above it is proportional, which is the correct split.
- The ellipsis policy is chosen per job, not uniformly: titles ellipsize End (`src/ui.rs:584`, `src/omnibox.rs:419`, `src/panels.rs:965`), URLs ellipsize Middle (`src/ui.rs:267` `max_width_chars(52)`, `src/panels.rs:969`), so the host and the tail of a path survive. The tab title also carries `hexpand(true)` + `max_width_chars(1)` (`src/ui.rs:585-587`) and the close button is packed after it at a fixed `18x18` (`:596`), so a long title cannot push the close out of the row.
- The live-row weight is set in exactly one place now and the comment explains why: `src/ui.rs:578-581` sets `Weight::Semibold` as a Pango attribute because "GTK's CSS wants keywords", and `.row.live .rowtitle` (`src/css.rs:166`) sets colour only. There is no longer a CSS weight fighting a Pango weight on the same label. Measured against the reference the result is close: live row `Office Commun` ref 92x10 ink 390 coverage 0.424, ours 100x10 ink 339 coverage 0.429.
- Weight is otherwise used with intent rather than everywhere: `.rowtitle` and `.newtablabel` are explicitly `normal` (`:165`, `:182`) so the theme cannot sneak a bold in, and only headings, caps group labels and chosen states are bold (`:174`, `:192`, `:213`, `:236`, `:260`, `:126`, `:249`, `:257`). Caps groups also carry tracking (`letter-spacing: 0.06em` `:213`, `0.07em` `:260`) instead of relying on size alone.

## What costs points

- **The whole scale is frozen at 100% and ignores the desktop's font setting.** 35 absolute `font-size:` px values in `src/css.rs`, no `em`/`rem`/`%` anywhere (`grep -o "font-size: [0-9]*px" | sort | uniq -c` → 10px ×2, 11px ×11, 12px ×10, 13px ×9, 15px ×3; `grep -c line-height` → 0), and `~/.config/gtk-3.0/settings.ini` says `gtk-font-name=Noto Sans,  10`. A user who raises their system font to 14pt gets a window whose type never moves, because no rule is relative to `gtk-font-name` and nothing reads `text-scaling-factor` (`grep -rn "text-scaling\|font_name\|font-name" src/` → no hits). Smallest fix: express the ladder in `em` off one root size set from `gtk-font-name` (or multiply each of the 35 values by a single `SCALE` constant read from `GtkSettings`), and add `line-height: 1.3` to the body rules while there. Costs 0.7.
- **Six sizes that are really three, one pixel apart.** `10px` (`:213`, `:260`), `11px` (`:194`, `:229`, `:230`, `:237`, `:244`, `:245`, `:261`, `:262`, `:11px`-class rules at `:242`), `12px` (`:124`, `:135`, `:140`, `:193`, `:197`, `:208`, `:219`, `:247`, `:251`, `:272`) and `13px` (`:191`, `:228`, `:239`, `:243`, `:259`, `:265`) all do body/secondary duty, then `15px` jumps for headings (`:192`, `:207`, `:236`). Measured, the ranks are indistinguishable: secondary text renders 8px tall (`.settingdesc` `Rules enforced inside the engine…` 306px wide, 8px x-height) and a *label* renders 9px (`.act` `Show them` 62x9); the group head `BROWSING` (10px bold caps, `:260`) and the group head `Today` in history (`.ptgroup` 11px bold, `:242`) are the same rank 1px apart, and one is caps while the other is not. Smallest fix: collapse to four values — 10px caps head, 12px secondary, 13px body, 15px title — map `.ptgroup` onto `.group`, and delete one of the two 1px-adjacent body steps. Costs 0.5.
- **Rows of the Shortcuts sheet paint outside the card, and the two type systems inside it show the seam.** The card's bottom border is at y≈779 in both looks (`05-panel-shortcuts.png` column scan at x=1195: 239 → 225 → 163 → 255 at y=778-780; dark: 26 → 39 → 102 → 255 at y=778-779; history ends at y=691-692). Below that line the list keeps drawing: `F5` at y≈818, `Ctrl F5` at y≈858, `Ctrl Shift R` at y≈898, with keycap fill `#D1D1D0` (light) / `#5A5A5A` (dark) on the bare page and the `.setting` 13px descriptions ghosted to gray 237-255 on white. The cause is `body_scroll` using `PolicyType::Never` (`src/panels.rs:291`), `card.set_size_request(680, 420)` (`:69`) and `wanted.clamp(200, 640)` (`:190`), and the row pitch is ~40px for an 11px/13px pair, so 28 rows cannot fit. What it exposes typographically is that the keycap is mono 11px (`:245`) while its description is proportional 13px (`:259`) with no shared baseline rule. Smallest fix: `self.body.add(&self.body_scroll(&list))` for the shortcuts body and `.keycap { font-size: 12px }` so the chip and its label differ by one rank, not two. Costs 0.6.
- **The fake address field is 2px smaller than the real one it turns into.** `.fakefieldtext` is 13px (`src/css.rs:191`) and `.omnitext` is 15px (`:207`), built in `src/ui.rs:193-224`. Measured: the placeholder `Search or enter an address` in `08-empty.png` is 160x9, and the same string at 15px is 183px wide; the real path `/office` in `04-omni.png` renders 38x11 and the `Ctrl L` hint beside the fake field is 41x8 (mono 11px). So clicking the imitation field makes the text grow two ranks. The same row also mixes 12px `.omnisite` with 15px `.omnitext` (`:208`, `:207`): the host `127.0.0.1` measures 56x13 and the path 38x11, and their baselines sit 1-2px apart in the 8x crop. Smallest fix: `.fakefieldtext { font-size: 15px }` and put `.omnisite` at 13px so the host/path pair differ by one rank. Costs 0.4.
- **Every button label's weight is inherited from the theme, not chosen by the browser.** The stock-skin reset (`src/css.rs:101-116`) strips `background-image`, `box-shadow`, `text-shadow`, padding and border — but never `font-weight`. `/usr/share/themes/adw-gtk3-dark/gtk-3.0/gtk.css:402` sets `button { … font-weight: bold }`, and this machine's `gtk-theme-name` is `adw-gtk3`. A live GTK probe (Gtk.OffscreenWindow, this provider at `STYLE_PROVIDER_PRIORITY_APPLICATION`) reports label-node weight 400 under `Adwaita` and **700** under `adw-gtk3` for both `button.act label` (`:124`) and `.panel button.tab label` (`:247`), neither of which sets a weight. The evidence set hides it because `tools/shots.sh` unsets `DISPLAY` and uses a clean config: measured in `05-panel-settings.png`, `Show them` is 62x9 with a white-run plurality of 63-81 (Regular; synthetic bold would be 67 wide, h1=5), `Bookmarks` resting tab is 60px wide with h1=80 (Regular), and only `Settings` (chosen, h1=2 h2=37) and `Light` (chosen) are bold, i.e. exactly the rules that name a weight win. On a real adw-gtk3 desktop every one of these becomes bold. Smallest fix: add `font-weight: normal;` to the `button` reset at `src/css.rs:107-115`. Costs 0.4.
- **The find bar puts a theme-sized input next to an 11px status.** `src/find.rs:33` is a bare `gtk::Entry::new()` with no class, so it renders at `gtk-font-name` (10pt ≈13.3px), while `.findbar label` is 11px (`src/css.rs:269`) and beats `.empty`'s 13px (`:265`) on specificity. In `06-find.png` the query `Paragraph` measures 64-70x14 and `399 matches` measures 77x8 inside a 34px-tall bar (`src/find.rs:31`) — a 14px glyph box and an 8px one, unaligned, in one control. Smallest fix: give the entry a class and `.findbar entry text { font-size: 13px }`. Costs 0.3.
- **Live is not semibold, because the font has no semibold.** `fc-match "Noto Sans:weight=semibold"` → `Noto Sans Bold 200`; only Regular/Bold/Italic/BoldItalic exist on this box. `Weight::Semibold` (`src/ui.rs:580`) therefore snaps to Bold, and the live row's only marks are bold + colour. In `01-default.png` the live title measures 100px wide versus 92px for the reference (`reference/reference-window.png`), and the idle rows (`Notion` 39x9 coverage 0.330) sit a whole step below. Smallest fix: pin the family's real intermediate weight — `FONT` should name a family that ships one (`Inter` does) or the live state should use `Weight::Medium` with `font-feature-settings` fallback — otherwise drop the comment at `:578` that claims a weight that is not rendering. Costs 0.3.
- **Two definitions of one idea, and one dead rule.** `.keycap` (`src/css.rs:245`: `background {chipbg}`, `padding 2px 6px`) and `.keyhint` (`:261`: `background {wash}`, `padding 1px 5px`) both render mono 11px key chips, and in `05-panel-shortcuts.png` the in-card chips are invisible (`(560,264)` is `#EFEFEF`, identical to the card fill) so the only visible chip in the build is the broken one outside the card. `.suggest .sgkind` is 11px at `:230` and has no call site at all (`grep -rn "sgkind" src/` returns one hit, the CSS). Smallest fix: delete `.sgkind` and `.keyhint`, keep `.keycap`. Costs 0.1.
- **Two truncation mechanisms for the same string.** Tab rows use Pango ellipsis (`src/ui.rs:584-587`); bookmark chips are cut in Rust by `short_title` (`src/app.rs:166-177`: 26 chars, prefer a space after 12, append U+2026) and the bar scrolls instead of truncating (`src/ui.rs:170-174`). The same long title therefore truncates at a different place in the bar and the row, and no screenshot in the corpus exercises either: the longest title available is `Office Commun` at 100px of a 213px row. Smallest fix: drop `short_title`'s 26-char cut and give `.bmark` the same `EllipsizeMode::End` + `max_width_chars` treatment used for `.rowtitle`. Costs 0.2.
- **No line heights anywhere, so wrapped copy is set by accident.** `grep -c line-height src/css.rs` → 0; only the reader sheet sets one (`assets/reader.js:65` `font: 19px/1.62`, `:68` h1 `34px/1.18`). Chrome leading is GTK's default ≈1.27, visible in the only three-line description in the corpus (`Use less memory`, bands 533-542 / 547-556 / 561-570 = 14px pitch on 11px type). The primary reference's own body copy is set much airier (`19px/1.62`), so the app's densest text and its reader mode disagree by a wide margin. Smallest fix: `line-height: 1.35` on `.settingdesc`, `.bmark`, `.purl` and `.sgurl`. Costs 0.2.

## The three changes that would raise this score most

1. Make the ladder relative and give it fewer steps: one root size from `gtk-font-name`, four stops (10 caps / 12 secondary / 13 body / 15 title) replacing the current 10/11/12/13/15 set at `src/css.rs:191-272`, with `.ptgroup` folded into `.group` and `line-height: 1.35` on the secondary rules.
2. Give the shortcuts sheet a scroller (`.body_scroll` at `src/panels.rs:291`) so its rows stop painting past y≈779, and set `.keycap` to 12px (`src/css.rs:245`) so the chip and the 13px label it belongs to read as one pair.
3. Make the browser own its button weight instead of inheriting the theme's: add `font-weight: normal;` to the `button` reset at `src/css.rs:101-116`, and set `.fakefieldtext` to 15px (`:191`) so the empty page's field matches the real one it becomes.
