## What is right

- The pin band and the first row land on the reference's coordinates. Pins occupy `y=65..99` in both pictures; tile columns are ref `(9,42) (47,80) (85,119) (124,157)` vs build `(10,44) (48,82) (86,120) (124,158)` — 34px tiles on a 38px pitch against 35px on 38px, gaps 4 vs 3. First row text starts `y=119` ref vs `y=113` build in `02-pins.png`; the row pitch is 30px against the reference's 30-31px.
- The page block is on the same baseline: heading ink ref `y=378..390 x=573..691`, build `y=377..390 x=575..699`; button ink ref `y=579..617`, build `y=589..628`; the paragraph breaks match line 1 (`y=419..433` vs `420..434`), line 3 (`471..486` both) and line 4 (`511..527` vs `512..526`). `tools/demo/office.html:18` nudges the block by `translateY(41px)` and it worked.
- `08-empty.png` centres its hint on the page column, not the window: block `x=696..1035`, centre 865 against the page column's centre 866 for the divider at 232.
- The Linux-native window controls are the sanctioned difference and are correctly placed as a 22px cluster at `y=22..27` inside the 40px `topband` (`src/ui.rs:88-99`, `src/css.rs:82`), so pins still land at `y=65` exactly. The square window corners (`src/css.rs:64-67`, `radius = 0`) are explained in the comment there and are a deliberate adaptation.

## What costs points

- **The column divider does not exist.** Reference: `x=232` reads `srgba(236,236,236)` at `y=40`, `300`, `600` and `900`, with antialias neighbours `x=231 = 249` and `x=233 = 253`. Build: every column `x=226..240` is a single colour (`255,255,255`) for the whole of `y=24..917`, at every y probed, in all 15 light shots; dark `01-default.png` at `x=300,800` is the page's own white, not a drawn line. Both `.side` and the page are white because `src/palette.rs:124-126` returns `self.card` for `side_bg()`, so the divider is the only thing that distinguishes the two columns, and it is absent. `src/ui.rs:75` `paned.set_wide_handle(false)` with `pack1(&side, false, false)` leaves `src/css.rs:77` (`paned > separator { min-width: 1px; background-color: {divider} }`) with nothing to paint. The project's own instrument already says so: `tools/compare.py` prints `"column": null` for the shot against `232` for the reference, and `difference` omits `column` entirely, so nothing caught it. *Smallest fix:* `src/css.rs:80` → `.side {{ background-color: {sidebg}; border-right: 1px solid {divider}; }}` (and the same for `.shell`'s page side in dark). *Cost: 1.2 points* — it is the whole silhouette of the app.
- **The 24px window chrome band above the page is missing.** Reference: rows `y=0..23` are non-white across the full width (`y=5` run is `0..1499`, colour `237,237,236`), and at `x=800` the ramp is `237 → 232` over `y=0..22` then pure white from `y=24`. Build: `x=800, y=0..23` is `srgb(255,255,255)` — the page, not a band. The 40px `topband` (`src/ui.rs:88`) exists only inside the sidebar column and is transparent. Reference's band ends exactly where the divider begins (`y=24` run: `(0,10) (231,232) (1496,1499)`), which is why removing it also removes the divider's start. *Smallest fix:* give `paned.pack2(&card, …)`'s card a 24px `background-color` strip in `237,237,236` (a new `.chrome` box above the page stack in `src/ui.rs` around line 263), or accept the omission explicitly in `docs/`. *Cost: 0.6 points* — the top edge of the window reads as page content rather than window.
- **Sidebar type is markedly heavier and darker than the original.** Live row title, matched boxes: ref `x43..133 y119..129` mean `200.8` min `7`; build `x43..141 y83..93` mean `163.2` min `14` — roughly 1.8x the ink, and 99px wide against 91px for the same string. `src/css.rs:154` sets `.row.live .rowtitle { font-weight: bold }` (700); the reference is semibold. Pin letters are worse: ref tile 1 minimum ink over `9..42 x 65..99` is `193` (a near-invisible #C1), build is `106`; row letter tiles ref min `132` vs build `106`. `src/css.rs:27` `PIN_FG = 0x6A6A68` and `src/css.rs:35` `TILE_FG = 0x6A6A68` are deliberate WCAG picks (commented as 4.80-5.47:1, tested by `every_text_pair_passes_wcag` in `src/palette.rs:199`), so the *colour* is a defensible trade; the *weight* is not. *Smallest fix:* `font-weight: 600` on `src/css.rs:154`, and run the stand-in's chrome through `FONT` at 12.5-13px to recover the 8px width delta. *Cost: 0.5 points.*
- **The stand-in page does not match the original's typography, so two line breaks land differently.** `tools/demo/office.html:12` makes the inline links `<b>` at `font-weight: 600` and `:13` removes their underline; the reference shows them *underlined* at body weight (`Public`, `Workspaces`, `Premune`, `hello@officecommun.com`, `Instagram`, `X`, `LinkedIn` are all underlined in the reference crop of `y=471..486`). Line 2 ends `x=1122` at "…the first question" in the reference and `x=1138` at "…question to" in the build; line 5 ends `1092` vs `1125`. *Smallest fix:* `main { width: 570px }` at `tools/demo/office.html:18` and replace `b { font-weight: 600 }`/`a { text-decoration: none }` with underlined links at normal weight. *Cost: 0.4 points.*
- **Font substitution is unmitigated.** `src/palette.rs:135` starts the stack with `"SF Pro Text", "SF Pro", Inter`, but on this machine `fc-match "SF Pro Text"` and `fc-match Inter` both resolve to `NotoSans-Regular.ttf`, so every label renders in Noto. The heading is `573..691` (119px) in the reference and `575..699` (125px) in the build for the same 17px string. *Smallest fix:* ship Inter (already first in the family list after the SF names) in `assets/` and register it, or accept it in `docs/`. *Cost: 0.3 points* — partly unavoidable on Linux, but the fallback that was chosen is the wrong one of the two.
- Nit: the row pill starts at `x=10` (`src/ui.rs:138` `rows.set_margin_start(10)`) and the reference at `x=8`; the pill radius reads 7 in the reference profile (`y=110 → 14, 111 → 12, … y=116 → 8`) and about 5 in the build (`y=75 → 14, 76 → 12, 77 → 11, 78..102 → 10`) against `border-radius: 7px` at `src/css.rs:151`. 2px, left alone.
- Evidence caveat: `council/round-33/manifest.json` calls `01-default` "one tab, the studio page", but the sidebar shows two tabs (`N New tab` at `y=51..66` and the live `Office Commun` at `y=75..102`), so that shot is not directly comparable to the reference, whose first row is the live tab. `02-pins.png` is the comparable one and is where the good geometry numbers above come from.

## The three changes that would raise this score most

1. Paint the column's hairline: 1px `{divider}` right border on `.side` (`src/css.rs:80`), because the paned separator never draws at `set_wide_handle(false)` and the two columns are otherwise identical white for the full 917px height.
2. Restore the 24px full-width chrome band above the page (`237,237,236`, ref `y=0..23`), so the top of the window reads as a window and the divider starts at `y=24` like the reference.
3. Bring the sidebar type back to the reference's weight and size: `font-weight: 600` instead of `bold` on `src/css.rs:154`, and fix `tools/demo/office.html:18` (`main { width: 570px }`) plus the bold-instead-of-underlined link style at `:12-13` so the stand-in page wraps where the original does.
