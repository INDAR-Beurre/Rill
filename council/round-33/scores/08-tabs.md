## What is right
- Geometry matches the reference to a few pixels: our active pill is `x 10..222`, `y 195..222` (213x28) against the reference's `x 11..219`, `y 112..137` (209x26); row text and letter tiles sit at the same inset, and the reference's letter-on-tile treatment (A/G/A) is reproduced rather than replaced by a generic globe (`src/ui.rs:453-478`).
- Active vs resting are distinguished by three things at once: fill `#EFEFEF` vs transparent, ink `#0E0E0E` vs `#6A6A68`, and Pango semibold (`src/css.rs:152-154`, `src/app.rs:483-488`). The resting ink is not guessed: `src/css.rs:31-33` records that `#6E6E6E` fell to 4.43:1 on a hovered row and moved to `#6A6A68`.
- Close is per-row, hover-only, and cannot disturb the layout: `opacity: 0` until `.row:hover` (`src/css.rs:148-149`), fixed `18x18`, `set_can_focus(false)`, packed after a `hexpand` title (`src/ui.rs:490-504`). The title is `EllipsizeMode::End` with `max_width_chars(1)`, so a long title cannot push the close out.
- Row height has one source (`src/store.rs:135-140`: 28, or 36 with Roomy tabs) feeding both `.row { min-height }` (`src/css.rs:147`) and `event.set_size_request` (`src/ui.rs:459`), plus the New-tab row (`src/app.rs:826`), so the setting changes the list coherently. The list is in a `ScrolledWindow` with `PolicyType::Never/Automatic` and `vexpand` (`src/ui.rs:137-145`), so it does scroll rather than clip.

## What costs points
- **A sleeping tab reads exactly like a live one.** `asleep` is set in three places (`src/app.rs:244` on restore, `:414` on an empty new tab, `:1288` in `sleep_others`) and copied into the rebuild at `:767`, but `grep -n "asleep" src/ui.rs src/css.rs` returns nothing: no class, no dimming, no mark. With `Let tabs sleep` on by default (`src/panels.rs:578`) and every restored tab starting asleep, the user clicks a row that looks live and waits for a page to be built with no explanation. Smallest fix: take `tab.asleep` in `tab_row`, add `.row.asleep .rowtitle { color: {faint} }` and a half-opacity tile. One point.
- **Nothing in the list shows a tab loading.** `tab.loading` is set at `src/web.rs:174` and `:187`, and read only by `src/keys.rs:239` and the bench JSON (`src/bench.rs:439`); `tab_row` (`src/ui.rs:453`) has no loading parameter and there is no throbber anywhere in `src/*.rs` (`grep -i "spinner\|throb\|progress"` finds nothing). A tab that is still arriving is indistinguishable from one that finished. Fix: pass `loading`, draw a 12px arc in the 18px icon holder in place of the letter. One point.
- **A private tab is not marked in the list, though a check says it is.** `tab.private` (`src/app.rs:39`) is copied at `src/app.rs:762` and never reaches a widget. The passing check `a private tab is marked private` asserts only `any(tab["id"] == private and tab["private"] for tab in probe["tabs"])` (`tools/stress.py:864-866`), i.e. the state field, not the picture; its detail line is "tab 55". The check's name overstates the evidence. Fix: a mask glyph in the tile for private rows, or a 1px dotted left border. One point.
- **The active row is not kept in view, and the list has no keyboard path.** `select` (`src/app.rs:431-446`) re-renders and grabs focus on the *web view*, never touching `rows_scroll.vadjustment()`; the only scroll-to in `src/` is the omnibox's (`src/omnibox.rs:509`). Rows are `EventBox`es and the close is `can_focus(false)` (`src/ui.rs:503`), and `src/keys.rs:160-193` has `Ctrl Tab`, `Ctrl Page Down`, `Ctrl 1 to 9` and nothing that moves through the list. At the default 30px pitch in an 800px column 20 tabs happen to fit, so this only bites at 40 tabs or with Roomy tabs in a short window, and no picture in this round shows more than six rows (`03-tabs.png`) plus "22 tabs" from the JSON, so the claim is unverified both ways. Fix: after `render()` in `select`, scroll the row's `allocation().y()` into the adjustment. Half a point.
- **Reorder is absent and unstated.** `grep -rn -i "reorder\|move_tab\|insert_tab\|drag tab" src/ docs/ README.md` returns nothing, and `docs/DIFFERENCES.md` lists what is not ported (Services, Share, Handoff, iCloud tabs, Spaces, full-screen gestures) without mentioning tab order. Fix: one line in `docs/DIFFERENCES.md`. Quarter point.
- **The close button is an unnamed control.** `tab_row` builds it with `gtk::Button::new()` and never sets a tooltip or an accessible name, while every other icon button gets both through the `make` closure at `src/ui.rs:303-317`. Fix: copy those two lines onto `close`. Quarter point.
- **Hover and active are only 7 levels apart in light, and hovering the active row paints nothing.** `hover` is `#F6F6F6` and `wash` is `#EFEFEF` (`src/palette.rs:106-107`), and because `.row:hover` (`src/css.rs:151`) precedes `.row.live` (`:152`) at equal specificity, the live fill wins: the row you are on never acknowledges the pointer. Dark is fine (`#272727` vs `#3A3A3A`). Fix: darken the light hover to `#F1F1F0` and add `.row.live:hover { background-color: {hairline} }`. Quarter point.
- **No evidence of ellipsis in the pictures.** Corpus: `02-pins.png` and `03-tabs.png` show "Office Commun" whole, so no screenshot exercises a title wider than 213px. Code path is right (`src/ui.rs:490-493`), but it is asserted, not shown. Not scored separately; fixing one of the states above with a long title would close it.

## The three changes that would raise this score most

Give the row a second state: pass `asleep`, `loading` and `private` into `tab_row` (`src/ui.rs:453`) and add `.row.asleep` (dimmed title, half-tone tile), `.row.loading` (arc in the icon holder) and a private mark. Three unwired booleans are already sitting in the rebuild at `src/app.rs:762-767`; this is one signature and three CSS rules.
2. Scroll the active row into view in `select` (`src/app.rs:431`), using the `rows_scroll` adjustment the sidebar already owns, so 40 tabs and Roomy tabs cannot hide the row you just switched to.
3. Say what the list cannot do: add tab reordering to `docs/DIFFERENCES.md`, and give `close` the accessible name and tooltip the other icon buttons already have (`src/ui.rs:303-317`).
