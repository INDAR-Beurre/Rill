## What is right

- Curtain injection is closed twice over. `sanitized` (src/curtain.rs:136) refuses `<`, `"`, `'`, `{`, `}`, `,`, `\n`, `\r` and a trailing backslash, one bad selector costs only its own rule because `css_from` skips it (src/curtain.rs:26-36), and the surviving CSS reaches the page as `serde_json::to_string(&css)` into `style.textContent` (src/curtain.rs:113-118), so a `<` cannot end the script even if the first gate were widened later. The page-posted selector is also sanitized before storage, not after (src/curtain.rs:236).
- Download names cannot leave the directory. `safe_filename` (src/web.rs:496) takes the last path component, drops NULs, refuses `.` and `..`, strips leading dots, caps at 200 chars and falls back to "download"; `unique_path` (src/web.rs:514) re-sanitizes, and the panel row is built from the name actually used (src/web.rs:389), so the record and the disk cannot disagree. The tests at src/web.rs:643+ cover `../../.bashrc`, a Windows path, an absolute path, `.`, `..`, an embedded NUL and whitespace.
- Archive install is a properly bounded unpack. src/extensions.rs:605-680 has four limits (256MB archive, 16MB entry, 128MB total, 4096 entries), skips symlink entries, checks `enclosed_name()` plus Normal components, checks the declared size against the running total and still caps the copy with `.take(limit)`, and `remove_at` (src/extensions.rs:753) refuses anything not under the root. `*://*.example.com/*` does not match notexample.com: src/extensions.rs:286 tests `host == base || host.ends_with(".{base}")`, with the lookalike case pinned at src/extensions.rs:1097.
- Writes are atomic and private. `write_private` (src/files.rs:62) creates `create_new(true)` with `mode(0o600)`, `sync_all`s, chmods, then renames within the directory; `temp_path` (src/files.rs:128) mixes pid, subsecond nanos and an `AtomicU64` counter, so two instances and two threads cannot pick the same name. Errors are per tab: `show_error` (src/app.rs:1902) keys an error on the tab id and refuses to overwrite an existing one, so a background tab that fails cannot steal the front one's page, and `error_pressed` (src/app.rs:1993) sends a 4xx to "Change address" and everything else to retry.

## What costs points

- The memory termination is not handled. src/web.rs:282 returns for every reason that is not `Crashed`, so `ExceededMemoryLimit` and `TerminatedByApi` leave a dead view with no message and no retry: the user sees a grey frame that never recovers, on the exact host this project runs on ("a memory spray is survived" passes because the spray is measured, not because the tab recovers). Smallest fix: drop the `matches!` guard and pass the reason into `show_error` with its own sentence ("This page ran out of memory."), keeping `Crashed`'s wording for `Crashed`. Cost: 4 lines, one test entry.
- No navigation policy at all. src/web.rs:296-305 is `is_some() && false`, so a page can navigate its own tab to `file:///home/you/.ssh/id_rsa` or to a `data:` URL with no scheme allowlist, and no `connect_permission_request` handler exists anywhere in src/ (grep "permission" finds only manifest fields and file modes), so geolocation, notifications and media requests all fall to WebKit's silent default while `set_enable_developer_extras(true)` (src/web.rs:77) is on. Smallest fix: in that handler, allow `http`, `https`, `file` only when the request comes from a `file` page, and `about`/`data` only for the initial load, returning ignore otherwise; add `view.connect_permission_request` denying with a `PermissionRequest` for everything but `Notification` on https. Cost: ~30 lines.
- Nothing caps tabs. `new_tab` (src/app.rs:443) has no limit and every tab is a separate web process (10 processes already at 980MB in the spray check), so a page that calls `window.open` in a click loop, or a self-reloading page a person leaves open, grows without bound until the engine is the thing that dies. `unique_path` and the store are capped; the live set is not. Smallest fix: a `MAX_TABS` of 40 in `new_tab` that shows the 41st request as a message in the current tab instead of creating it. Cost: 6 lines.
- `downloads_dir` (src/web.rs:472) ends in `PathBuf::from(".")`, so with neither `XDG_DOWNLOAD_DIR` nor `HOME` set a download lands in whatever directory the browser was started from, silently. Smallest fix: `PathBuf::from("/tmp")` or, better, refuse the download with a message when neither variable exists. Cost: 1 line (or 5 for the message).
- tools/stress.py:986 asserts `abs(width-1200) <= 40 and abs(height-780) <= 40` against the probe's `allocated_width()` (src/bench.rs:478), which is the JSON field, not the painted area, and the 40px tolerance means a 1160x740 window passes a check named "the window survives resizing". Nothing clicks the error page's own buttons either: grep for "Try again", "Change address", "retry" in tools/stress.py finds nothing, so `error_pressed` and `retry` are only exercised by unit tests, and no fixture serves a hostile `Content-Disposition` (tools/fixtures.py:177 offers only `filename="fixture.bin"`), so `safe_filename` has never run against a real server's text. Smallest fix: tighten the tolerance to 4px and assert the inner view's allocation, add a fixture sending `filename="../../.bashrc"` and assert the file appears in the download dir under the fallback name, and add a check that presses `errorAction` on a 404 and asserts the omnibox address is unchanged and the tab is still there.

## The three changes that would raise this score most

1. Handle every `WebProcessTerminationReason` at src/web.rs:282 with its own sentence, including the low-memory one, so a dead tab always says what happened and offers retry.
2. Answer permission requests and add a navigation scheme allowlist at src/web.rs:296, so a page cannot pull a local file into itself and cannot silently ask for the microphone.
3. Cap tabs at src/app.rs:443 and stop stress.py:986 from passing on the JSON allocation instead of the window's contents.
