## What is right
- Each of the three has a real empty state with a next step, and the card shrinks to it instead of leaving a slab: `panels.rs:296` "Nothing kept yet. Ctrl D keeps the page you are on.", `:323`, `:383`, rendered as a 240px card in `05-panel-bookmarks.png` (card y=340..581).
- Records are correct: newest-first, one row per address, page titles backfilled, private tabs kept out. `store.rs:224` `history.retain(|e| e.url != url)` then `insert(0, …)`, `store.rs:239` `name_visit`, `app.rs:1053-1057` skips `tab.private`. `ago()` (`store.rs:273`) gives "just now / 1 min ago / 2 hr ago / yesterday".
- Persistence is careful and private: `files.rs:71-93` `create_new(true)`, `.mode(0o600)`, `sync_all` before `rename`, then `set_permissions` again; `private_dir` makes only the directories it creates `0o700`; `temp_path` (`files.rs:127-139`) is `name.pid.nanos.counter.tmp` so two writers cannot share a name. Tests `a_written_file_is_owner_only` and `overwriting_an_existing_file_keeps_it_owner_only` cover it.
- The bookmarks bar and the panel agree on set and order, both from `state.bookmarks` (`app.rs:621-626` vs `panels.rs:294`); the panel shows the bookmark's title with the URL as subtitle (`panels.rs:302`), never a bare URL.

## What costs points
- **Downloads show no progress and no size, and cannot be opened.** `DownloadRec` is `{name, path, done}` only (`app.rs:80-84`); there is no `connect_estimated_progress` or `connect_received_data` anywhere (`grep -rn "estimated_progress\|received_data\|content_length" src/` returns only `set_destination`, `web.rs:377`). A running row reads "Downloading to /path" (`panels.rs:389`) with nothing more, and the only button is "Reveal" on the parent folder (`:390-397`); there is no open-the-file action. Smallest fix: add `got: u64, total: u64` to `DownloadRec`, feed them from those two signals, render "12.4 of 40 MB", and add an "Open" action calling `xdg-open <path>`. Costs 0.7.
- **No panel can remove one entry.** Every row is built by `link_row` with exactly one action: history "Open" (`panels.rs:359`), bookmarks "Open" (`:302`), downloads "Reveal" (`:390`). The only deletion is "Clear History" (`:334`), which wipes and reloads in one click with no confirm and no undo (`:340-341`), and bookmarks have no clear at all (`grep -rn "bookmarks.clear()" src/` hits only `bench.rs:331`). Removing a bookmark means navigating to the page and pressing Ctrl D (`app.rs:1564`). Smallest fix: a second optional action on `link_row` ("Remove") wired to `history.retain`/`bookmarks.retain` + save + rebuild, and a confirm on Clear History. Costs 0.6.
- **The history filter only searches the newest 300 of up to 4000.** `panels.rs:357` `history.iter().take(300).filter(…)` runs before the filter, while the header prints the full length (`:329` "{} pages", capped at `store.rs:233` `truncate(4000)`). Searching for an older page returns an empty list, and there is no "no matches" line at all (`grep -rn "No match\|no results\|Nothing matches" src/` returns nothing). Smallest fix: `.filter(…).take(300)`, plus one `empty_state` label when the filtered list is empty. Costs 0.5.
- **A server-supplied download name is joined unsanitized, so a name can escape the downloads folder.** `web.rs:366-376` takes `suggested_filename()` (or the URL tail) straight into `unique_path`, which does `dir.join(name)` (`:419`). A name of `../../.bashrc`, or an absolute path (where `join` discards `dir`), writes outside `~/Downloads`. `grep -rn "sanitiz\|basename\|replace" src/web.rs` finds nothing. The only download check in `build/stress-report.json` records `"name": "download"` at `/tmp/search-stress-6fw3hyfm/downloads/download`, so no name with a separator is ever exercised. Smallest fix: `let suggested = suggested.rsplit('/').next().unwrap_or("download").replace(['\\','\\0'], "_")` and drop leading dots, before `unique_path`. Costs 0.5.
- **A failed download keeps saying it is downloading.** `web.rs:397-401` only calls `flash_error("That download failed")`; the record is never changed, so `done` stays `false` and `panels.rs:389` renders "Downloading to …" forever. Smallest fix: add `failed: bool` set in that closure and render "Failed" in the subtitle. Costs 0.4.
- **Downloads vanish on restart.** `app.rs:263` `downloads: Vec::new()` and no `downloads.json` exists anywhere (`grep -c "downloads.json" src/*.rs` is 0 in every file), although `store.rs` persists session, history, bookmarks and hidden. After a relaunch the panel is empty while the files sit in `~/Downloads`. Smallest fix: a `Records::load_downloads/save_downloads` pair mirroring bookmarks, written when a download finishes. Costs 0.3.
- **History is one flat list with relative times only.** `panels.rs:357-366` emits rows in visit order with `ago(entry.at, now)` and nothing else; `ago` (`store.rs:273-284`) tops out at `"N days ago"`, so a month later every row reads "43 days ago". No "Today"/"Yesterday" separators and no absolute date or time anywhere. A picky reviewer opens this list asking "what did I read on Tuesday" and cannot answer. Smallest fix: section labels from `entry.at` in local time (Today, Yesterday, then a date) inserted between rows. Costs 0.3.
- **The history card clips its seventh row.** In `05-panel-history.png` the card's bottom border is the row at y=692 (`magick … -crop 1x1+800+692` = `srgb(148,148,146)`, white at y=694) yet the last row's "Search" title sits at y=686 and its URL at y≈702, on the page below the card; the "Open" button is cut in half by the same edge (`/tmp/h_bottom.png`). Dark matches (`05-panel-dark` border y=692 `srgb(110,110,110)`, row text at y=702). No scrollbar is drawn (x=1195..1198 at y=520 is `srgb(239,239,239)`), so the cut looks like a layout fault, not a scroll. Cause: the magic `+ 140` at `panels.rs:174` under-measures head + nav + count header + filter (measured 174px). Smallest fix: sum those four heights explicitly instead of 140, and land the card on a row boundary. Costs 0.2.
- **Bookmarks cannot be renamed, and the bar switch cannot hide the bar.** No rename path exists in `src/` (`grep -rni "rename" src/*.rs` gives only `files.rs` temp-file renames and `serde(rename_all)`); a page kept under a junk title stays junk. Meanwhile `app.rs:628` builds the bar when `prefs.show_bookmarks_bar || !state.bookmarks.is_empty()`, so turning "Show the bookmarks bar" off (`panels.rs:590-597`) does nothing while any bookmark exists. Smallest fix: `show_bookmarks_bar && !state.bookmarks.is_empty()`, and an edit field on the bookmark row. Costs 0.3.
- **Wording and dead space.** `panels.rs:329` prints `"{} pages"` unconditionally, so one entry reads "1 pages". The "Reveal" targets and the sentence naming the destination folder ("Files you download land here and in your Downloads folder", `:383`) exist only in the empty state, so a list of finished files never says where they are. Costs 0.2.

## The three changes that would raise this score most
1. Downloads: carry `got`/`total` from `connect_estimated_progress`/`connect_received_data`, print "12.4 of 40 MB" plus a state ("Downloading", "Done", "Failed"), add an "Open" action beside "Reveal", and persist the list like bookmarks (`panels.rs:375-405`, `app.rs:80-84`, `web.rs:355-401`).
2. A "Remove" action on every history, bookmark and download row, and a confirm (or undo toast) on "Clear History" (`panels.rs:334-343`, `:292-405`).
3. One line in `web.rs:366-376` that strips `/`, `\` and leading dots from the server's filename before `unique_path` joins it to the downloads dir, plus a stress check that a hostile `Content-Disposition` lands inside `~/Downloads`.
